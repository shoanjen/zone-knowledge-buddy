## 2. 已修复缺陷

### 2.1 数据正确性 / 状态机

| # | 问题 | 修复 |
|---|------|------|
| 1 | 文档先置 `ready` 再做分块向量化，前端会看到 `chunk_count=0` 的假就绪态 | `parsing` 状态保持到 embedding 完成；`rag/pipeline.py` 成功后置 `ready`，失败置 `failed` |
| 2 | 分块/写 Chroma 抛非 `GatewayError` 时只写日志，文档永久停在 ready 且无法重试 | pipeline 捕获异常落 `failed+error`；dispatcher 兜底并记录 |
| 3 | 纯表格 Markdown 被判 `empty` | 空文档判据纳入 `table` 块 |
| 4 | Excel 表头推断把 `None` 当非空（`str(None)` 为真），无表头首行被当表头丢失；标题取存储名 `original` | 非空判断排除 `None`；无表头补系统列名；标题回退上传文件名 |
| 5 | 批量上传中后一个文件非法会让前面已入库文档永久 `pending`（无响应 id、无后台任务） | 先校验全部文件再落库；多文件返回 `items + errors`（202），单文件仍 415/413 |
| 6 | PDF 表格块统一插到本页正文之前，阅读顺序错乱 | 按页内坐标排序表格与文本块 |
| 7 | 分块重叠丢失【章节】前缀，且把上一块全部 `block_ids` 声明为本块来源 | 重写分块：前缀恒存在；仅继承尾部 50 字实际覆盖的 block_id；章节边界不携带 |
| 8 | Agent 观测结果直接 `json.dumps(...)[:4000]` 后 `json.loads`，长结果必崩 | 结构化截短，保证仍为合法 JSON；超限退化为 `preview` |

### 2.2 笔记 / 任务

## 5. 环境限制与未覆盖项（如实声明）

1. **真实云端模型未联调**：仓库 `.env` 未配置有效的云端 Key；本机 Ollama 的 `/v1/chat/completions` 实测不可用（原生接口 20 token 约 49s，OpenAI 兼容端点 180s 无响应）。因此 Agent/SSE/报告链路使用本地 OpenAI 兼容模拟网关，**HTTP、DB、Chroma、SSE、报告渲染均为真实链路**；向量仍走真实 `bge-m3`。
2. **Playwright 浏览器内核未安装**：网页导入验证的是 trafilatura 静态抽取路径；JS 渲染页仍需 `playwright install chromium`。
3. **未实现 SSE 15s 心跳与 300s 总时长上限**（断开取消已补）；未做 URL 导入的内网地址拦截（单机单用户假设下未列入本期）。
4. **未改动的既有边界**：OCR 不做（仅标 `parse_quality=low`）、多用户/改密为 P2、`docker-compose` 未提供；这些与 README“未完成 / 已知边界”一致。
5. 列表接口仍有 N+1 查询、报告/笔记部分交互未做性能优化；不影响功能验收。
