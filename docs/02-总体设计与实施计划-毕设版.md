### 2.1 关键架构决策（论文「总体设计」素材）

1. **单体分层而非微服务**：单人单机场景，部署简单、答辩演示稳定；模块间以服务类接口隔离，保留了拆分余地。
2. **LLM 网关统一收口**：所有模型调用经过同一网关模块，供应商差异（本地 Ollama / 云端 API）在网关内抹平——两者都支持 OpenAI 兼容协议，切换 = 改 base_url + api_key + 模型名。网关统一记录每次调用的 Token 数与耗时，直接产出论文实验数据。
3. **向量模型固定本地**：切换云端只影响「生成类」调用（整理/问答/报告）；embedding 始终用本地 bge-m3，避免供应商切换导致向量语义漂移、整个向量库作废重算。
4. **Agent 通过工具注册表访问业务能力**：解析、检索、笔记写入、图表生成都是注册的工具，Agent 内核与业务解耦，新增能力 = 注册新工具。
5. **隐私分级**：资料存储、向量库始终本地；生成类推理默认云端（界面常驻标识当前推理位置与 Token 用量），用户可随时切换本地小模型实现全离线。
6. **本地运行时抽象**：Ollama 与 LM Studio 均视为「OpenAI 兼容本地端点」，网关内同一 Provider 实现，切换只改 base_url 与端口（11434 / 1234）；LM Studio 的 MLX 引擎作为 Apple Silicon 推理提速备选。

## 3. 核心模块设计

### 3.1 解析层：统一文档中间表示（DocumentIR）

五种格式各自解析后归一为同一 JSON 结构，是全系统的数据枢纽：

```json
{
  "doc_id": "d_20261019_001",
  "source": { "type": "pdf|word|md|excel|web", "origin": "文件名或URL", "imported_at": "..." },
  "meta":   { "title": "...", "author": "...", "pages_or_sheets": 12, "parse_quality": "high|low" },
  "blocks": [
    { "block_id": "b1", "type": "heading",   "level": 1, "text": "研究背景" },
    { "block_id": "b2", "type": "paragraph", "text": "..." },
    { "block_id": "b3", "type": "table",     "caption": "...", "data": [["列1","列2"],["...","..."]] },
    { "block_id": "b4", "type": "image",     "ref": "storage路径", "ocr_text": null }
  ]
}
```

**设计价值**：解析器之间互不干扰；下游（分块、Agent、报告、溯源）只面对一种结构；引用溯源以 `doc_id + block_id` 为锚点，天然可点击回跳原文。

**各格式解析器（P0 基础能力）**：

| 格式 | 库 | 说明 |
|------|-----|------|
| PDF | PyMuPDF | 文本 + 标题层级 + 表格；检测为扫描件时标记 `parse_quality=low` 并提示（OCR 作为可选加分项接入 PaddleOCR） |
| Word | python-docx | 标题/段落/表格 |
| MD | markdown-it-py | 原生结构 + frontmatter 元数据 |
| Excel | openpyxl + pandas | 多 sheet、表头推断、类型识别；每个 sheet 转为一个 table block |
| 网页 | trafilatura + Playwright | 正文抽取去噪；JS 渲染页面走 headless 浏览器；失败降级并明确提示 |

### 3.2 Agent 层：自研 ReAct 风格编排

```
意图理解 → 任务规划(生成步骤列表) → 循环[ Thought → Tool Call → Observation ]
        → 综合生成 → 引用校验反思 → 输出（笔记/报告/回答）
```

**反思环节（本设计的质量控制核心）**：逐条检查生成结论是否携带引用、引用的 chunk 是否真实存在、内容是否被该 chunk 支撑；不满足则补一次检索重写或删除该条。这一步是论文的创新点素材之一，也是对比实验的变量（见 §6）。

**工具注册表（P0）**：

| 工具 | 功能 |
|------|------|
| `kb.search(query, top_k)` | 知识库语义检索，返回 chunk + 来源 |
| `kb.read(doc_id, block_range)` | 读取原文块，供引用核对 |
| `doc.list / doc.summary` | 文档清单 / 单文档摘要（长文走 Map-Reduce） |
| `note.write` | 写入/更新结构化笔记 |
| `chart.spec(data, intent)` | 将表格数据转为 ECharts option JSON |
| `report.render` | 汇聚章节 + 图表 + 引用，渲染交互式 HTML |

**本地小模型与云端协同适配（工程约束，论文可写）**：
- 上下文有限 → 长文档摘要用 Map-Reduce（分块摘要再归并），检索片段控制在 3–4k token。
- 本地 4B 小模型结构化输出更不稳（兜底通道预期内）→ Ollama structured output / JSON mode + 宽松 schema 校验 + 失败重试；质量敏感任务默认走云端。
- 本地/云端同一套 Prompt 与工具协议，便于做「本地小模型 vs 云端」质量对比实验。

### 3.3 RAG 问答与引用溯源

- **分块**：按 DocumentIR 章节边界切，目标 500 字/块、重叠 50 字；表格整表一块。
- **检索**：bge-m3 向量 top-k（k=5 起步，论文可做 k 消融）。
- **回答约束**：Prompt 强制「仅依据检索片段回答，每条结论标注 [doc_id:block_id]」；前端把引用渲染为可点击、展开显示原文片段。
- **拒答行为**：检索无支撑时明确回答「知识库中未找到依据」——评测中计为正确拒答，不编造。

### 3.4 交互式报告生成

```
选定文档集 + 报告意图 → Agent 产出大纲 → 逐章生成(带引用)
→ 含 Excel 源数据时生成图表 spec → Jinja2 渲染单文件 HTML → 预览/下载/分享
```

报告页能力：侧边目录导航滚动联动；ECharts 图表可交互（悬浮数值/缩放）；点击引用号折叠展开原文；自包含单文件（内联 CSS/JS），可直接打开或部署到任意静态服务器分享。

### 3.5 Web 端与数据模型

**页面清单**：登录（极简单用户）· 工作台（导入 + 任务概览）· 文档库 · 笔记详情（可编辑）· 报告列表/预览 · 知识问答 · 任务面板 · 设置（**模型供应商切换**、参数、数据管理）。

**API 模块**：`auth` · `documents`（上传/解析状态）· `notes` · `reports` · `chat`（SSE 流式）· `tasks` · `settings`（含供应商配置）。

**核心表**：`user`、`document`、`block`、`chunk`（含向量 id）、`note`、`note_citation`、`report`、`chat_session`、`chat_message`、`agent_task`（步骤与状态）、`llm_provider`（供应商配置：类型 local-ollama / local-lmstudio / cloud、base_url、api_key 加密、模型名、启用状态）。

**模型切换语义**：`llm_provider` 中同一时刻恰有一个「生效」配置——本地 Ollama、本地 LM Studio、云端供应商三者同层对待、切换语义一致；切换立即生效于后续所有生成类调用；进行中的任务沿用发起时的供应商并在任务记录中留痕（论文可追溯每个结果由哪个模型/运行时生成）。接口与配置规格见《03-实现方案细化》。

## 5. 毕设创新点与工作量呈现（写论文/答辩用）

1. **多格式统一解析中间表示（DocumentIR）**：五类异构格式归一为同一结构化模型，一套下游管线完成分块、整理、溯源、渲染。
2. **轻量 Agent 编排方法**：规划—工具执行—引用校验反思三阶段循环，本地/云端供应商无关（同一实现），可解释、可复现。
3. **块级引用溯源的本地 RAG 问答**：结论强制锚定原文块，支持可拒答、可点击核验，抑制幻觉。
4. **本地/云端模型统一网关与可切换架构**：OpenAI 兼容协议抹平供应商差异，向量模型固定本地保证知识库稳定，支持同题对比评测。
5. **数据驱动的交互式报告自动生成**：Excel 数据 → Agent 生成图表规格 → 自包含交互式 HTML。

## 6. 测试与评价方案（论文实验章节素材）

| 实验 | 方法 | 产出指标 |
|------|------|---------|
| 功能测试 | ~30 条用例覆盖五格式导入/整理/问答/报告/模型切换 | 通过率、缺陷清单 |
| 解析质量 | 每格式抽 5 份真实资料，人工标注要点 | 要点召回率 |

| 生成忠实度 | 抽查生成笔记/报告结论，逐条核对原文 | 引用支撑率、幻觉率 |
| 性能 | 记录端到端各阶段耗时与 Token（LLM 网关自动采集） | 解析/整理耗时、首字延迟 |
| **模型对比** | 同一任务集：云端 API vs 本地 qwen3:4b（顺带论证「云端主力 + 小模型兜底」策略的合理性） | 整理质量、忠实度、耗时、成本四维对比 |
| **消融实验** | 直接问模型 vs RAG vs RAG+引用校验反思 | 正确率/忠实度提升，验证设计有效性 |

## 9. 工程风险与对策（毕设语境）

| 风险 | 对策 |
|------|------|
| 云端 API 不可用（断网 / 限流 / 额度耗尽） | 生成类调用重试 2 次 → 提示切换本地小模型兜底（qwen3:4b，质量降级属预期并记录）；Token 用量统计 + 预算提醒 |
| 本地小模型兜底时整理质量不稳 | 任务拆小（单文档摘要→多文档归并）；Few-shot 提示；低温度；引用校验兜底；质量敏感任务回切云端，均记录对比数据 |
| Ollama 上下文限制 | Map-Reduce 摘要；检索片段控制在 3–4k token |
| 网页抓取受阻（反爬/动态渲染） | Playwright 多策略 + 纯文本降级 + 明确失败提示 |
| 扫描件 PDF | 明确列为非目标：检测后提示「质量受限」，OCR 作为可选加分项 |
| 进度延期 | 保底策略见 §7；每阶段结束系统必须可启动、可演示 |
