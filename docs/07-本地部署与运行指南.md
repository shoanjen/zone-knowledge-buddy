# 07 · 本地部署与运行指南

> 适用对象：拿到本项目源码、希望在**自己的个人电脑**（macOS / Windows / Linux）上把系统跑起来的同学、老师或评审。
> 本文只讲"怎么装、怎么跑、出问题怎么查"，不涉及代码实现；需求与设计见 `docs/01`～`docs/04`。

---

## 1. 系统概览

**zone-knowledge-buddy · 知识伙伴** 是一个基于大模型 Agent 的多格式个人知识管理系统：导入 PDF / Word / Excel / Markdown / 网页，自动解析、分块、向量化，然后通过 Agent 生成带可回溯引用的笔记、自包含 HTML 报告、双人播客音频，并提供 RAG 流式知识问答。

### 1.1 组成部分

```
┌──────────────────────┐      /api 代理       ┌──────────────────────────────┐
│  前端  Vue 3 + Vite   │  ─────────────────▶ │  后端  FastAPI (Python)       │
│  http://localhost:5173│                      │  http://localhost:8000        │
└──────────────────────┘                      │   ├─ SQLite   (业务数据)       │
                                              │   ├─ ChromaDB (向量库)        │
                                              │   └─ 本地文件 (原文/报告/音频)  │
                                              └───────────┬──────────────────┘
                                                          │ OpenAI 兼容接口
                              ┌───────────────────────────┼────────────────────────┐
                              ▼                           ▼                        ▼
                   ┌────────────────────┐    ┌─────────────────────┐   ┌────────────────────┐
                   │ Ollama (本地,必需)  │    │ 智谱 GLM 云端 (可选) │   │ LM Studio (可选)    │
                   │ bge-m3  → 向量化    │    │ glm-4.6 → 生成主力   │   │ qwen3 等 → 本地生成 │
                   │ qwen3:4b→ 本地生成  │    │ 需 API Key + 联网    │   │                    │
                   └────────────────────┘    └─────────────────────┘   └────────────────────┘
```

所有业务数据（SQLite、向量库、上传原文、报告、音频）都保存在本机磁盘，**不依赖任何外部数据库服务**，部署非常轻量。

### 1.2 端口与地址一览

| 组件 | 默认地址 | 说明 |
|---|---|---|
| 前端开发服务器 | `http://localhost:5173` | 浏览器访问入口 |
| 后端 API | `http://localhost:8000` | 前端通过 Vite 代理把 `/api` 转发到这里 |
| 后端接口文档 | `http://localhost:8000/docs` | FastAPI 自动生成的 Swagger UI，可直接调试接口 |
| 健康检查 | `http://localhost:8000/api/health` | 返回 `{"status":"ok","version":"0.1.0"}` 即正常 |
| Ollama | `http://localhost:11434` | 本地模型服务（向量模型必需） |
| LM Studio | `http://localhost:1234` | 可选的另一种本地生成方案 |

## 2. 环境准备

### 2.1 软件清单

| 软件 | 版本要求 | 用途 | 是否必需 | 获取方式 |
|---|---|---|---|---|
| **Python** | ≥ 3.11 且 < 3.13（推荐 3.12） | 运行后端 | 必需 | <https://www.python.org/downloads/> 或由 uv 代装 |
| **uv** | 任意近期版本 | Python 依赖管理（推荐） | 推荐（可用 venv+pip 替代） | 见 §2.3 |
| **Node.js** | ≥ 20 LTS（含 npm） | 构建/运行前端 | 必需 | <https://nodejs.org/> |
| **Ollama** | 任意近期版本 | 运行向量模型 `bge-m3`（检索/问答/笔记/报告都依赖） | **必需** | <https://ollama.com/download> |
| **Git** | 任意 | 获取代码 | 可选（也可下载 zip） | <https://git-scm.com/> |
| **智谱 GLM API Key** | — | 云端大模型生成（效果最好） | 可选（可用本地 Ollama 生成替代） | <https://open.bigmodel.cn/> |

> **为什么 Ollama 是必需的？** 系统的向量化（embedding）固定走本地 Ollama 的 `bge-m3` 模型，与"生成"用哪个模型无关。没有向量模型，文档就无法入库检索，问答、笔记、报告都无法工作。

### 2.2 硬件与网络建议

| 项目 | 建议 |
|---|---|
| 内存 | 8 GB 起（仅跑 `bge-m3` 向量 + 云端 GLM 生成）；若还要本地跑 `qwen3:4b` 生成，建议 16 GB |
| 磁盘 | 预留 ≥ 5 GB（Python/Node 依赖约 1.5 GB，`bge-m3` 约 1.2 GB，`qwen3:4b` 约 2.6 GB） |
| 显卡 | 非必需。Ollama 在 CPU 上也能跑 `bge-m3`；有独显会明显更快 |

**哪些功能需要联网：**

| 阶段 / 功能 | 是否需要联网 |
|---|---|
| 首次安装依赖、拉取模型 | 需要 |
| 使用云端 GLM 生成（笔记/报告/问答） | 需要 |
| 使用本地 Ollama / LM Studio 生成 | 不需要 |
| 播客音频合成（edge-tts，调用微软在线语音服务） | 需要 |
| 网页 URL 导入 | 需要（访问目标网页） |
| 文档解析、向量检索、查看笔记/报告 | 不需要 |

### 2.3 安装 uv（推荐的 Python 依赖管理器）

uv 会自动创建虚拟环境并按锁文件 `uv.lock` 精确安装依赖，确保所有人环境一致。

```bash
# macOS / Linux
curl -LsSf https://astral.sh/uv/install.sh | sh

# Windows PowerShell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

# 或者任意平台已有 pip 时
pip install uv

# 验证
uv --version
```

如果本机没有合适版本的 Python，uv 可以直接代装：

```bash
uv python install 3.12
```

> 不想用 uv？可以跳过本节，后端部署时选择"方式 B：venv + pip"（§4.2），项目已提供 `backend/requirements.txt`。

### 2.4 安装并验证 Node.js

从 <https://nodejs.org/> 下载 LTS 版本安装（或用 nvm / fnm 管理）。验证：

```bash
node --version   # 应 ≥ v20
npm --version
```

国内网络建议切换 npm 镜像以加速：

```bash
npm config set registry https://registry.npmmirror.com
```

### 2.5 安装 Ollama 并拉取模型

1. 从 <https://ollama.com/download> 下载安装对应系统的 Ollama（桌面版安装后会自动在后台运行服务）。
2. 拉取模型：

```bash
ollama pull bge-m3        # 必需：向量模型，约 1.2 GB
ollama pull qwen3:4b      # 可选：本地生成模型，约 2.6 GB（没有 GLM Key 时用它来生成）
```

3. 验证服务在线、模型已就位：

```bash
curl http://localhost:11434/api/tags
# 返回的 JSON 中应能看到 "bge-m3"
```

> 如果 Ollama 没有自动启动（常见于 Linux），手动执行 `ollama serve` 并保持该终端开着。

## 4. 部署后端

以下命令都在 `backend/` 目录下执行：

```bash
cd backend
```

### 4.1 方式 A：使用 uv（推荐）

```bash
# 1. 安装依赖（自动创建 .venv，首次约 2～5 分钟，视网络而定）
uv sync

# 2. 生成配置文件
cp .env.example .env            # Windows CMD 用:  copy .env.example .env

# 3. 生成密钥（下一步要填进 .env）
uv run python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

国内网络若 `uv sync` 很慢，可使用镜像：

```bash
UV_DEFAULT_INDEX=https://pypi.tuna.tsinghua.edu.cn/simple uv sync
# Windows PowerShell:  $env:UV_DEFAULT_INDEX="https://pypi.tuna.tsinghua.edu.cn/simple"; uv sync
```

### 4.2 方式 B：使用标准 venv + pip

```bash
# 1. 创建并激活虚拟环境（确认 python 指向 3.11 或 3.12）
python3 -m venv .venv
source .venv/bin/activate       # Windows:  .venv\Scripts\activate

# 2. 安装依赖
pip install -r requirements.txt
#   国内可加镜像: pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple

# 3. 生成配置文件
cp .env.example .env            # Windows CMD 用:  copy .env.example .env

# 4. 生成密钥（下一步要填进 .env）
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

### 4.3 编辑 `.env` 配置

用任意编辑器打开 `backend/.env`，把上一步生成的密钥填到 `KB_SECRET_KEY=` 后面。**这是唯一必填项**，其余保持默认即可启动。各配置项含义：

| 配置项 | 默认值 | 说明 |
|---|---|---|
| `KB_SECRET_KEY` | （空，**必填**） | Fernet 密钥，用于加密落库的 API Key。不填后端会拒绝启动 |
| `KB_ENV` | `dev` | `dev` 开启 CORS 与详细日志，本地部署保持 `dev` |
| `KB_ADMIN_USERNAME` | `admin` | 首次启动自动创建的登录账号 |
| `KB_ADMIN_PASSWORD` | `admin123` | 对应密码（只在**首次建库**时生效，之后改这里不会更新已有账号） |
| `KB_DATA_DIR` | `./data` | 运行期数据目录（相对于启动目录，即 `backend/data/`） |
| `EMBEDDING_BASE_URL` | `http://localhost:11434/v1` | 向量模型服务地址（Ollama） |
| `EMBEDDING_MODEL` | `bge-m3` | 向量模型名 |
| `KB_MAX_UPLOAD_MB` | `100` | 单文件上传大小上限 |
| `KB_MAX_UPLOAD_FILES` | `20` | 单次批量上传文件数上限 |
| `KB_CORS_ORIGIN` | `http://localhost:5173` | 允许跨域的前端地址 |
| `GLM_BASE_URL` | `https://open.bigmodel.cn/api/paas/v4` | 智谱 GLM 接口地址 |
| `GLM_API_KEY` | （空） | 智谱 API Key，可留空稍后在设置页填写（推荐，加密落库） |
| `GLM_MODEL` | `glm-4.6` | 云端生成模型名 |

填好后的最小 `.env` 示例：

```ini
KB_SECRET_KEY=这里粘贴刚生成的一长串密钥
KB_ENV=dev
KB_ADMIN_USERNAME=admin
KB_ADMIN_PASSWORD=admin123
KB_DATA_DIR=./data
EMBEDDING_BASE_URL=http://localhost:11434/v1
EMBEDDING_MODEL=bge-m3
KB_MAX_UPLOAD_MB=100
KB_MAX_UPLOAD_FILES=20
KB_CORS_ORIGIN=http://localhost:5173
GLM_BASE_URL=https://open.bigmodel.cn/api/paas/v4
GLM_API_KEY=
GLM_MODEL=glm-4.6
```

### 4.4 启动后端

```bash
# 方式 A（uv）
uv run uvicorn app.main:app --reload --port 8000

# 方式 B（venv 已激活）
python -m uvicorn app.main:app --reload --port 8000
```

首次启动会自动：创建 `backend/data/` 目录、建表并执行迁移、创建默认账号 `admin / admin123`、写入三条模型供应商预设（`cloud-glm`、`local-ollama`、`local-lmstudio`）。终端看到类似下面的输出即成功：

```
WARNING kb 已初始化默认用户 'admin'（请尽快修改密码：见 README）
INFO:     Uvicorn running on http://127.0.0.1:8000 (Press CTRL+C to quit)
INFO:     Application startup complete.
```

另开一个终端验证：

```bash
curl http://localhost:8000/api/health
# {"status":"ok","version":"0.1.0"}
```

或浏览器打开 <http://localhost:8000/docs> 查看接口文档。

> `--reload` 表示代码变动时自动重启，便于开发；纯演示可去掉。
> **保持这个终端开着**，后端运行期间不要关闭。

## 6. 首次登录与配置模型供应商

### 6.1 登录

默认账号：**`admin`**，密码：**`admin123`**。

### 6.2 启用一个生成模型（关键步骤）

系统启动后默认**没有启用任何生成模型**，此时生成笔记/报告/问答会提示 `PROVIDER_CONFIG` 错误——这是预期行为，需要先到「设置 → 模型供应商」启用一个。三种方案任选其一：

| 方案 | 适用情况 | 操作 |
|---|---|---|
| **cloud-glm（推荐）** | 有智谱 API Key、能联网，效果最好 | 点编辑 → 填入 API Key →「测试」通过 →「启用」 |
| **local-ollama** | 没有 Key / 想完全离线 | 先 `ollama pull qwen3:4b` → 直接「测试」→「启用」（无需 Key） |
| **local-lmstudio** | 已在用 LM Studio | LM Studio 中加载模型并开启本地服务（端口 1234）→「测试」→「启用」 |

启用成功后，页面顶栏的当前模型角标会变绿并显示模型名。

> 智谱 API Key 获取：注册 <https://open.bigmodel.cn/>，在控制台「API Keys」页创建。新用户通常有免费额度，足够毕设演示使用。

### 6.3 关于向量模型的注意事项

- 向量模型固定使用本地 Ollama `bge-m3`，与上面的"生成模型"是两回事，无需在设置页额外配置。
- **首次成功入库文档后，向量模型会被锁定**（防止不同模型的向量混用导致检索失效）。之后若想更换向量模型，设置页会返回 409 提示，需要先清空所有文档再改。

## 7. 验证部署（冒烟测试）

按以下顺序走一遍，全部通过即部署成功：

1. **上传文档**：在工作台上传 `samples/样例-项目调研报告.pdf`，到「文档」页等待状态变为「就绪」，块数 > 0。
   - 如果一直卡在"解析中"或变"失败"，大多是 Ollama / `bge-m3` 没就位，见 §12 FAQ。
2. **知识问答**：到「问答」页提一个与文档内容相关的问题，应看到流式输出的回答，并带有可点击的引用标记，点击能跳回原文片段。
3. **生成笔记**：上传第二份文档（如 `samples/样例-技术选型分析.md`），发起"对比笔记"任务，到「任务」页看时间线（思考 / 工具 / 观察 / 反思节点），完成后在「笔记」查看产物。
4. **生成报告**：发起报告生成，预览自包含 HTML（含目录、图表、引用），可下载。
5. **（可选）播客**：需联网，生成双人对话音频并在线播放。

也可以用命令行快速验证后端链路：

```bash
# 健康检查
curl -s http://localhost:8000/api/health

# 登录拿 token
TOKEN=$(curl -s -X POST http://localhost:8000/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"admin123"}' \
  | python3 -c 'import sys,json;print(json.load(sys.stdin)["token"])')

# 测试 1 号供应商（cloud-glm）连通性
curl -s -X POST http://localhost:8000/api/settings/providers/1/test \
  -H "Authorization: Bearer $TOKEN"
```

## 8. 日常运行

每次使用需要**三个服务同时在线**，建议按以下顺序启动：

| 顺序 | 服务 | 命令 | 说明 |
|---|---|---|---|
| 1 | Ollama | 桌面版自动运行；Linux 执行 `ollama serve` | 向量化依赖它 |
| 2 | 后端 | `cd backend && uv run uvicorn app.main:app --port 8000` | 保持终端开着 |
| 3 | 前端 | `cd frontend && npm run dev` | 保持终端开着 |

然后浏览器访问 <http://localhost:5173>。

**停止**：在各终端按 `Ctrl + C`。

**重启后的自愈行为**：如果后端在有任务进行中时被关闭，重启时会把中断的文档解析 / Agent 任务统一标记为 `failed`（终端会打印警告），重新发起即可；处于"等待确认"状态的任务会保留，重启后仍可批准或拒绝。

## 10. 数据目录、备份与重置

后端在 `backend/` 目录启动时，所有运行期数据位于：

```
backend/
├── data/
│   ├── kb.sqlite3     # 业务数据库（用户、文档元数据、笔记、任务、会话、设置、加密后的 Key）
│   ├── chroma/        # ChromaDB 向量库
│   ├── storage/       # 上传的原始文件
│   └── podcasts/      # 生成的播客 MP3
└── reports_output/    # 生成的自包含 HTML 报告
```

- **备份 / 迁移到另一台电脑**：停止后端，整体拷贝 `backend/data/` 与 `backend/reports_output/` 两个目录即可（注意新机器的 `KB_SECRET_KEY` 必须与原来相同，否则库里加密的 API Key 无法解密，需在设置页重填）。
- **完全重置（恢复到全新状态）**：停止后端，删除上述两个目录，重新启动后端即会重建数据库并重新创建 `admin` 账号。
- **忘记密码 / 想改默认账号**：V1 没有改密接口。修改 `.env` 中 `KB_ADMIN_USERNAME` / `KB_ADMIN_PASSWORD`，然后按"完全重置"操作一次（会清空所有数据）。
- 系统也提供「设置 → 数据导出」功能，可下载包含全部数据的 zip 包。

> `data/`、`reports_output/`、`.env` 均已在 `.gitignore` 中，不会被提交到仓库。

## 12. 常见问题（FAQ）

**Q1：后端启动报 `RuntimeError: KB_SECRET_KEY 未配置`**
`.env` 文件不存在或 `KB_SECRET_KEY` 为空。按 §4.3 生成密钥并填入，确认文件名是 `.env` 而不是 `.env.example`，且位于 `backend/` 目录下。

**Q2：`uv sync` 或 `pip install` 报 Python 版本不满足**
本项目要求 Python ≥ 3.11 且 < 3.13（3.13 暂不支持，部分依赖尚无对应版本）。执行 `uv python install 3.12` 让 uv 代装，或自行安装 3.12 后重建虚拟环境。

**Q3：端口 8000 或 5173 已被占用**
后端换端口：`--port 8001`；前端随之设置 `KB_BACKEND_URL=http://localhost:8001`（见 §5）。前端换端口：`npm run dev -- --port 5174`，同时把 `.env` 的 `KB_CORS_ORIGIN` 改成 `http://localhost:5174`。

**Q4：上传文档后一直"解析中"，或最终变成"失败"**
最常见原因是向量化失败：Ollama 未运行或 `bge-m3` 未拉取。检查 `curl http://localhost:11434/api/tags` 是否能看到 `bge-m3`；修复后在文档页点「重试」。

**Q5：问答 / 笔记 / 报告提示 `PROVIDER_CONFIG` 错误**
还没有启用任何生成模型。按 §6.2 到设置页「测试 → 启用」一个供应商。

**Q6：云端 GLM「测试」失败**
依次检查：API Key 是否复制完整、本机能否访问 `open.bigmodel.cn`、账户额度是否用尽。可改用 `local-ollama` 方案临时替代。

**Q7：想更换向量模型，设置页返回 409**
向量模型在首次入库后已锁定。需先删除全部文档（或按 §10 完全重置），再修改。

**Q8：上传 `.txt` 文件返回 415**
当前支持的格式为 PDF、Word（.docx）、Excel（.xlsx）、Markdown（.md）以及网页 URL。纯文本可改为 `.md` 后缀上传。

**Q9：扫描版 PDF 解析出来内容为空或很少**
系统不做 OCR，扫描件会被标记为"低质量"。请使用含文字层的 PDF。

**Q10：网页 URL 导入抓不到正文**
目标页面可能依赖 JS 渲染。按 §11 安装 Playwright 的 Chromium 内核后重试；若目标站有反爬/登录墙则无法抓取。

**Q11：播客生成失败**
播客使用 edge-tts 调用微软在线语音服务，必须联网且能访问微软服务。网络受限环境下该功能不可用，不影响其他功能。

**Q12：Windows 下 `source .venv/bin/activate` 报错**
Windows 使用 `.venv\Scripts\activate`（CMD / PowerShell）。若 PowerShell 提示禁止运行脚本，先执行 `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`。

**Q13：Windows 下没有 `curl` / `cp` 命令**
Windows 10 以后自带 `curl.exe`；`cp` 换成 `copy`。或者直接用浏览器打开 `http://localhost:8000/api/health` 与 `/docs` 做验证。

**Q14：重启后端后，之前的任务都变成了"失败"**
这是启动自愈的预期行为（§8）：进程退出时线程里的任务无法恢复，统一标记失败以免卡死；重新发起即可。

**Q15：`npm install` 很慢或超时**
切换镜像：`npm config set registry https://registry.npmmirror.com`，删除 `frontend/node_modules` 后重新 `npm install`。

## 13. 安全与注意事项

- 本系统面向**单用户、本机运行**的毕设场景设计，没有多用户隔离和权限体系，**不要**直接暴露到公网。
- 首次登录后请尽快把 `admin123` 换掉（方法见 §10），尤其是在局域网共享演示时。
- 智谱 API Key 建议通过设置页填写，会用 `KB_SECRET_KEY` 加密后存入数据库；不要把填好 Key 的 `.env` 发给别人或提交到仓库。
- `KB_SECRET_KEY` 一旦丢失，库中已加密的 Key 将无法解密，需重新填写；请妥善保存。
