> 配套《01-需求分析》v0.3、《02-总体设计与实施计划》、《03-实现方案细化》 · 2026-10-19
> 定位：**唯一开发主规格**——覆盖全部 P0/P1 功能的接口级开发定义，按本文档开发无需再做设计决策。

### 2.4 统一错误约定

**响应体**（所有非 2xx 一致）：

```json
{ "code": "PARSE_FAILED", "message": "PDF 解析失败：文件已加密", "detail": { "doc_id": "d_01J8..." } }
```

**异常层级**（`core/errors.py`，FastAPI handler 统一捕获 `AppError`）：

```
AppError(code, http_status, message, detail)
├── AuthError(401) / ForbiddenError(403) / NotFoundError(404)
├── ValidationError(422)          # 业务校验（非 pydantic 自动 422，handler 需归一格式）
├── UploadError(413/415)          # 超大小 / 格式不在白名单
├── ParseError(422)               # 解析失败，detail 带 doc_id 与原因
├── DocStateError(409)            # 状态机非法迁移（如对 parsing 中文档删除）
├── TaskStateError(409)           # 任务状态机非法操作
├── EmbeddingLockedError(409)     # 向量模型已锁定（§12.3）
├── GatewayError(502)             # LLM 端点不可达 / HTTP 错误（retryable 标记）
├── GatewayJSONError(502)         # 结构化输出重试耗尽仍不合法
└── InternalError(500)
```

**错误码表**（前端按 code 做文案与跳转，`AUTH_INVALID` → 登录页）：

`AUTH_INVALID` `FORBIDDEN` `NOT_FOUND` `VALIDATION` `UPLOAD_TOO_LARGE` `UPLOAD_FORMAT` `URL_INVALID` `PARSE_FAILED` `PARSE_UNSUPPORTED` `DOC_STATE` `TASK_STATE` `EMBEDDING_LOCKED` `PROVIDER_UNREACHABLE` `PROVIDER_CONFIG` `LLM_JSON_INVALID` `INTERNAL`

### 2.5 记账、ID 与时间约定

- **llm_call_log**：网关内 `chat/chat_json/embed` 每次调用各写一行（成功失败都写）；token 取响应 `usage`，流式在结束帧取（端点不支持则记 0）；`task_type` 取调用方传入（`extract/chat/report/embed/tool/planner/reflect`）。
- **ID**：`doc_id=d_{ulid}`、`chunk_id=c_{ulid}`、`note_id=n_{ulid}`、`report_id=r_{ulid}`、`task_id=t_{ulid}`；block 在文档内自增 `b1,b2,...`。ULID 保证按时间排序。
- **时间**：DB 一律 UTC ISO8601 字符串（如 `2026-10-19T12:34:56Z`），前端本地化展示。
- **日志**：结构化 logging，`request_id`（中间件生成 `req_{ulid}`）贯穿；LLM 调用日志关联 `task_id`。

## 4. M1 认证（极简单用户）

### 4.1 API

**POST `/api/auth/login`**

```json
// 请求
{ "username": "admin", "password": "..." }
// 200
{ "token": "eyJ...", "expires_in": 604800, "username": "admin" }
// 401 AUTH_INVALID（用户名或密码错误——统一文案，不区分）
```

**GET `/api/auth/me`**（新增，前端刷新时恢复会话）→ `200 {"username":"admin"}` / `401`。

### 4.2 实现约定

- JWT：PyJWT HS256；claims `{sub, iat, exp}`；有效期 7 天；密钥 = `HKDF(KB_SECRET_KEY, "jwt")`（与 Fernet 密钥隔离派生）。
- 密码：passlib bcrypt；首启建的默认账号在日志打印「请尽快修改密码」，修改密码接口为 P2 非目标，本期通过重置 `.env` + 删 `user` 行重建。
- `get_current_user` 依赖：解析 `Authorization: Bearer`，失效抛 `AuthError`；除 `/api/auth/login`、`/api/health` 外全部路由强制。

**验收**：错误密码 401 且文案统一；无 token 访问任意业务路由 401；token 过期后 401。测试要点：签发/过期/篡改三分支。

## 5. M2 LLM 网关（`app/llm/`）

### 5.1 对外接口（对《03》§2.1 的实现级固化）

```python
@dataclass
class GenerationParams:
    temperature: float | None = None   # None → 按 task_type 查 settings.generation_params
    max_tokens: int | None = None
    timeout_s: int = 120               # 流式首字节超时 30s 单独控制

class LLMGateway:
    def __init__(self, provider: LLMProviderRow): ...          # 快照生效供应商（§12.2）
    async def chat(self, messages: list[dict], *, task_type: str,
                   params: GenerationParams | None = None, stream: bool = False
                   ) -> str | AsyncIterator[str]: ...
    async def chat_json(self, messages: list[dict], schema: dict, *, task_type: str,
                        params: GenerationParams | None = None) -> dict:
        """3 次尝试：结构校验失败 → 追加错误信息重试；耗尽抛 GatewayJSONError"""
    async def embed(self, texts: list[str]) -> list[list[float]]:
        """固定通道：EMBEDDING_BASE_URL/MODEL，与 active provider 无关；批 16、批级重试 2"""
    async def healthcheck(self) -> HealthResult: ...           # GET {base}/v1/models，timeout 5s
```

**调用方获得**：`chat` 返回完整字符串或异步迭代器（逐 delta）；`embed` 顺序返回与输入等长。

### 5.2 三类端点差异（`providers.py` 唯一分支点）

| 差异项 | `cloud` | `local-ollama` | `local-lmstudio` |
|--------|---------|----------------|------------------|
| base_url 示例 | `https://open.bigmodel.cn/api/paas/v4` | `http://localhost:11434/v1` | `http://localhost:1234/v1` |
| 鉴权 | `Authorization: Bearer {key}`（必填） | 占位 `ollama` | 占位 `lmstudio` |
| 路径 | `/chat/completions` `/embeddings` `/models` | 同左 | 同左 |
| chat_json 实现 | `response_format={"type":"json_schema",...}`（按厂商支持降级 `json_object`） | `format="json_schema"` | `response_format={"type":"json_schema"}` |
| `<think>` 剥离 | —（云端一般无） | 网关响应层正则剥离 `<think>...</think>`（对 qwen3 系） | 同左 |
| 流式 usage | 结束帧（不支持则 0） | 同左 | 同左 |
| 默认模型（seed 数据） | `glm-4.6`（用户自填） | `qwen3:4b` | `qwen3:4b` |

结构化输出统一流程：`chat_json` 成功判据 = JSON 可解析 **且** 通过 `schema` 校验（`jsonschema` 库宽松模式：required + 类型，不校验 additionalProperties）。

### 5.3 记账与降级语义

- 每次调用写 `llm_call_log`（§2.5）；`ok=false` 时 `error` 存前 500 字符。
- 重试策略：网络/5xx/429 → 指数退避重试 2 次（1s/3s，仅非流式）；4xx 配置类错误不重试直接 `GatewayError(retryable=false)`。
- **不自动静默切换供应商**（对《03》§2.4 的重申）：生成失败重试耗尽 → 任务 `failed`，错误信息提示「可在设置页切换云端 ↔ 本地小模型后重试」。

### 5.4 seed 数据

首启写入三条 `llm_provider`（is_active 全 false，等待用户配置 key 后 activate）：`cloud-glm`(type=cloud, model=glm-4.6)、`local-ollama`(qwen3:4b)、`local-lmstudio`(qwen3:4b)。默认 `active_provider_id=null` → 首个生成类调用前必须完成 activate，否则抛 `PROVIDER_CONFIG`。

**验收**：mock 三端点各跑通 chat/chat_json/embed/healthcheck；`<think>` 剥离有单测；记账行数=调用数。测试要点：respx mock httpx；JSON 三次失败路径；超时路径。

```json
{ "items": [ { "doc_id": "d_01J8...", "filename": "论文A.pdf", "status": "pending" } ] }
// 413 UPLOAD_TOO_LARGE（单文件 > KB_MAX_UPLOAD_MB）
// 415 UPLOAD_FORMAT（扩展名不在白名单 .pdf .docx .md .xlsx）
```

**POST `/api/documents/url`**

```json
// 请求 { "url": "https://example.com/article" }
// 202 { "doc_id": "d_...", "status": "pending" }
// 422 URL_INVALID（非 http(s)）
```

**GET `/api/documents?page=1&page_size=20&source_type=&q=`**（q 匹配 title/origin，LIKE）→

```json
{ "total": 42, "items": [ { "id": "d_...", "title": "...", "source_type": "pdf",
  "origin": "论文A.pdf", "status": "ready", "parse_quality": "high",
  "block_count": 128, "chunk_count": 24, "imported_at": "..." } ] }
```

**GET `/api/documents/{id}`** → 上行列表项字段 + `blocks: [...]`（全量内联，>5000 块截断并在响应加 `"blocks_truncated": true`）+ `storage_path`（内部路径不出参，仅调试日志）。

**DELETE `/api/documents/{id}`** → `204`。**级联**：blocks、chunks、Chroma 向量（`where {"doc_id": id}`）、storage 目录、（若来源为 URL）无。笔记与引用**不删**（历史产出），引用点击时源不存在则前端提示「来源文档已删除」（§13）。
`409 DOC_STATE`：status=parsing 中不允删（先等待或取消）。

### 6.2 状态机与异步执行

```
pending → parsing → ready(parse_quality=high|low)
                  → failed(error 落 document 行, message 含原因码)
```

- 执行载体：`app/tasks/runner.py` 统一线程池（`ThreadPoolExecutor(max_workers=2)`），API 层 `BackgroundTasks` 投递；**不引入 Celery**（单机单用户，收益为负）。
- 解析完成即链式触发分块向量化（§7.2），同任务内完成；`chunk_count` 就绪后可见。
- 失败可重试：`POST /api/documents/{id}/retry`（新增）——仅 failed 可调，重置为 pending 重走管线。

### 6.3 DocumentIR（`parsing/ir.py`，pydantic 模型即契约）

```json
{
  "doc_id": "d_01J8...",
  "source": { "type": "pdf|word|md|excel|web", "origin": "文件名或URL", "imported_at": "ISO8601" },
  "meta":   { "title": "str|null", "author": "str|null", "pages_or_sheets": 0,
              "parse_quality": "high|low", "low_reason": "str|null" },
  "blocks": [
    { "block_id": "b1", "type": "heading",   "level": 1, "text": "研究背景" },
    { "block_id": "b2", "type": "paragraph", "text": "..." },
    { "block_id": "b3", "type": "table", "caption": "表1 参数对比",
      "data": [["列1","列2"],["...","..."]] },
    { "block_id": "b4", "type": "image", "ref": "storage/d_.../img_p3_1.png", "ocr_text": null }
  ]
}
```

落库映射：`block` 表每块一行（`data_json` 存表格/图片扩展字段）；`document.parse_quality` 冗余存 meta 值。

### 6.4 各格式解析规格

| 格式 | 提取规则 | 降级/边界 |
|------|---------|-----------|
| **PDF**（PyMuPDF） | 标题启发式：字号 > 全文众数字号×1.15 且长度<60 且（加粗或独立行）→ heading，level 按字号降序排名 1–4；正文合并断行（连字符去除断词）；`page.find_tables()` 命中区域从正文排除，转 table 块；图片导出到 storage 建 image 块 | 扫描件检测：>70% 页面文本 <30 字符 → `parse_quality=low, low_reason="scanned"`；加密文档 → ParseError("encrypted")；损坏 → ParseError |
| **Word**（python-docx） | 样式名 `Heading N` → heading level N；表格逐个转 table 块；内嵌图片导出 | `.doc` 旧格式不支持 → `PARSE_UNSUPPORTED`（提示转存 .docx） |
| **MD**（markdown-it-py） | token 流映射：heading_open→heading；paragraph→paragraph；table token→table 块；frontmatter（`---` 块）解析 title/author 进 meta | 空 md（无内容块）→ ParseError("empty") |
| **Excel**（openpyxl+pandas） | 每个**非空 sheet** 一个 table 块，caption=sheet 名；表头推断：首个非空行且下一行存在≥2种 pandas 类型 → 表头，否则无表头全量数据 | 合并单元格前向填充；空 sheet 跳过；>10 万行截断并 low_reason="oversize" |
| **网页**（trafilatura→Playwright） | 先直接抓 HTML → trafilatura.extract；结果 <200 字符 → Playwright headless 渲染（domcontentloaded+3s）后重抽；title 取 metadata | 二次仍 <200 字符 → ParseError("web_empty")；域名抓取失败（超时 30s/ DNS）→ ParseError("fetch_failed") |

**storage 约定**（`parsing/storage.py`）：原始文件存 `data/storage/{doc_id}/original{ext}`；图片 `{doc_id}/img_{page}_{n}.png`；文件名全部系统生成，杜绝用户输入进路径（§14）。

**验收**：每种格式 3 份真实样例（测试集见 §15）解析通过，块类型分布合理；扫描件被标 low；加密/空文档错误码正确。测试要点：PDF 标题启发式对两份真实论文的输出快照对比；网页降级链两次失败路径。

## 7. M4 分块与向量化（`app/rag/`）

### 7.1 chunking 算法（确定性，无 LLM）

输入：单文档有序 blocks。参数：目标 500 字/块、重叠 50 字（中文字符计）。

```
初始化 buf="", buf_blocks=[], section_path=[]
遍历 blocks（按 seq）：
  heading  → section_path 更新为该标题路径；若 buf 非空先收块
  paragraph→ buf += "\n" + text；buf_blocks += block_id
             若 len(buf) >= 500：收块，并将 buf 尾部 50 字作为下一块开头（重叠，block_ids 归属原块）
  table    → 先收 buf；表格独立成块：text = "【{section}】{caption}\n" + Markdown 序列化(data)
             （首行表头 | 分隔 | 数据行，单元格逗号转义）
  image    → 无 ocr_text 跳过；有则按 paragraph 处理（文本 = ocr_text）
收尾：残余 buf 收块
每块 text 前缀一行 "【章节】H1 > H2 > H3"（存在时），提高检索语义
```

产出写 `chunk` 表（`block_ids_json`、`text`、`vector_id` 预留 = chunk_id）。

### 7.2 向量化与 Chroma 约定

- 触发：解析 ready 后同任务链式执行；批量 `embed(batch=16)`，批失败重试 2 后整任务 failed（error 指明批次）。
- Collection：`kb_chunks`，cosine，dim 首次写入时探测；**id = chunk_id**；`documents = text`；`metadata = {doc_id, block_ids: "b1,b2"（逗号串）, section}`（Chroma metadata 仅标量，列表一律序列化）。
- 删除联动：删文档 → `collection.delete(where={"doc_id": id})` + 删 chunk 行。
- **首次写入向量前**：把 `settings.embedding` 落库并置 `locked_at`（此后换模型被拒，§12.3）。

### 7.3 检索服务与搜索 API

```python
class RagService:
    async def search(self, query: str, *, top_k: int = 5,
                     doc_ids: list[str] | None = None) -> list[SearchHit]
# SearchHit = {chunk_id, doc_id, block_ids: list[str], text, score, origin, title}
# score = 1 - cosine_distance；doc_ids 过滤用 where {"doc_id": {"$in": [...]}}
```

**GET `/api/search?q=&top_k=5&doc_ids=a,b`** → `{"results": [SearchHit...]}`（对《03》§4 的参数化细化）。

**验收**：500 字/重叠 50 的切分对样例文档的块数与边界符合人工核对；top-5 语义相关性抽检合理；删文档后检索无残留。测试要点：长段落跨块重叠正确；表格块独立；doc_ids 过滤生效。

## 8. M5 Agent 编排（`app/agent/`）

### 8.1 任务状态机与留痕

```
pending → planning → running → reflecting → done
                                    │
                (confirm_required)  ├→ paused → (confirm approve) → done
                                    │        └ (confirm reject)   → failed(user_rejected)
                任意执行态 → failed(error) / cancelled(用户取消，best-effort)
```

- `agent_task.input_json` 存入参快照；`provider_id` 发起时快照（可追溯）。
- `agent_task_step`：四类 step_type（thought/tool/observation/reflection）按序追加，`content_json` 存结构化内容；任务面板直接渲染（§12.1）。
- 执行载体复用 §6.2 线程池（与解析共享 max_workers=2）。

### 8.2 Planner（规划）

- 输入：任务类型（note/report）+ 用户 intent + 文档清单摘要（title+来源）。
- 输出（`chat_json`，schema）：

```json
{ "steps": [ { "no": 1, "description": "检索三份文档中关于成本的数据", "tool_hint": "kb.search" } ] }
```

- 约束：最多 6 步；planner 失败重试 1 次后降级为固定模板计划（检索→汇总→写作）。
- system prompt 要点：「你是任务规划器，只输出 JSON；步骤要具体、可执行、引用工具名」。

### 8.3 工具注册表（每个工具的接口契约）

| 注册名 | 入参（JSON Schema 摘要） | 返回 | 错误语义（作为 observation 返回，循环继续） |
|--------|------------------------|------|--------------------------------------------|
| `kb.search` | `{query: str, top_k: int=5}` | `{results: [SearchHit...]}` | 空结果返回空数组（不算错误） |
| `kb.read` | `{doc_id: str, block_ids: [str]}` | `{blocks: [{block_id,type,text,data}]}` | doc/block 不存在 → `{"error":"NOT_FOUND",...}` |
| `doc.list` | `{}` | `{docs: [{doc_id,title,source_type,chunk_count}]}` | — |
| `doc.summary` | `{doc_id: str}` | `{summary: str, block_count: int}` | not found 同上；长文走 Map-Reduce（§8.6） |
| `note.write` | `{title: str, content_md: str, tags: [str]}` | `{note_id: str}` | 仅 note 任务可用；内容为空 → error |
| `chart.spec` | `{data_source_block_id: str, intent: str}` | `{chart: {type,title,x_field,y_field}, echarts_option: object}` | 块非表格 → error；字段不在表头 → error |
| `report.render` | `{outline: 报告大纲JSON}` | `{report_id: str}` | 仅 report 任务最后一步可用 |

注册机制：`tools/registry.py` 提供 `@register(name, input_schema)` 装饰器；orchestrator 按任务类型过滤可用集合（note 任务无 report.render，report 任务无 note.write）。**工具内不调用 LLM**（chart.spec 的字段选择由 executor 层 LLM 决定后传入，工具只做确定性转换，保证可测）。

### 8.4 ReAct 执行循环（`orchestrator.py`）

- 每步 `chat_json` 输出（schema）：

```json
{ "type": "tool", "tool": "kb.search", "args": { "query": "..." } }
// 或
{ "type": "final", "content": "最终 markdown 产出" }
```

- 护栏：最大 12 步（planner 步数之外的工具往返计数）；单工具调用 60s 超时；同一 `(tool, args)` 连续调用 3 次 → failed("loop_detected")；observation 文本截断 4000 字符后回填上下文。
- 上下文组装：system（全局约束，见《03》§6）+ 任务意图 + 已执行步骤摘要（thought/tool/observation 压缩版）。

### 8.5 引用校验反思（`reflection.py`）

对 final 产出（笔记/报告章节）执行三查：

1. **格式查**：正则 `\[(d_[A-Za-z0-9]+:b\d+)\]` 提取引用标记；无任何标记且任务要求引用 → 整体重写 1 次。
2. **存在查**：每个 `doc_id:block_id` 在 DB 中存在（文档 ready 且块归属正确）；不存在的标记删除并记 reflection step。
3. **支撑查**：每条带引用的要点，把要点文本 + 引用块原文拼一次 `chat_json`（`{results:[{claim_id, supported: bool}]}`，批量单次调用）；不 supported → 该要点整句删除（保守策略，杜绝幻觉），记入 reflection step 供论文分析。

反思后产物进入 §8.1 的 done/paused 分支。

### 8.6 Map-Reduce 摘要（`doc.summary` 工具内）

- 阈值：文档全部 chunk 文本 > 6000 字符 → 走 Map-Reduce。
- Map：按 chunk 顺序每块生成 ≤100 字要点（并发 ≤4，复用网关）；Reduce：合并为结构化摘要（背景/方法/结论三段式 prompt）。
- 普通文档直接单次摘要。

**验收**：脚本化 mock 网关（固定响应序列）下跑通 plan→tool→final→reflect 全链；循环检测与步数上限各自触发 failed；反思删除要点后 note_citation 与正文标记一致。测试要点：工具注册表签名校验；observation 截断；paused→confirm 两条分支。

## 10. M7 知识问答（`app/api/chat`，SSE）

### 10.1 请求与 SSE 事件协议

**POST `/api/chat`**（`Accept: text/event-stream`）

```json
// 请求
{ "session_id": "s_... | null", "message": "三份报告里关于成本的说法有什么冲突？", "top_k": 5 }
```

**SSE 事件序列**（`sse-starlette`，15s 心跳；总体 300s 上限）：

```
event: meta       data: {"session_id":"s_...","message_id":"m_...","provider":{"type":"cloud","name":"GLM","model":"glm-4.6"},"retrieved":[{chunk_id,doc_id,score}]}
event: token      data: {"delta":"根据资料，"}
event: token      data: {"delta":"A 报告认为成本下降 [d_x:b12]..."}
...（流式若干帧）
event: citations  data: {"citations":[{"doc_id":"d_x","block_id":"b12","text":"原文片段...","origin":"A.pdf","title":"..."}]}
event: done       data: {"usage":{"prompt_tokens":0,"completion_tokens":0},"latency_ms":2340}
event: error      data: {"code":"PROVIDER_UNREACHABLE","message":"..."}   // 任一阶段失败即发并终止
```

- **断线语义**：不做 token 补发；done 前断开则该消息不留痕（客户端重发问题）。会话历史经 `GET /api/chat/sessions/{id}`（新增）拉取。
- 会话模型：`chat_session`（title=首条消息前 20 字）；`chat_message` 双向落库（assistant 的 `citations_json` 在 citations 事件时写）。

### 10.2 RAG prompt 与拒答

- 检索：`RagService.search(message, top_k)`；无结果或全低分（score<0.3）仍照常送 prompt（交由模型拒答，规则统一）。
- system（固定）：「仅依据资料片段回答；每条结论尾部标注 [doc_id:block_id]；资料不足以支撑时，只回答：知识库中未找到依据。禁止编造。」温度 `generation_params.chat`。
- 流式期间累积完整文本，done 前完成 citations 解析与落库。

**验收**：流式可渲染、引用可点击；自测集上无依据拒答正确率 ≥90%（W8 DoD）；切换供应商后 provider 字段即时反映。测试要点：mock 网关流式分帧；拒答分支；session 留痕。

### 12.2 供应商管理 API

| 方法路径 | 请求/响应要点 |
|---------|--------------|
| `GET /api/settings/providers` | 列表；**永不出参 api_key**，只给 `has_api_key: bool` |
| `POST /api/settings/providers` | `{type, name, base_url, model, api_key?}` → 201；type 枚举校验；cloud 缺 api_key → 422 PROVIDER_CONFIG |
| `PUT /api/settings/providers/{id}` | 同上字段均可改；不传 api_key 则保留原值 |
| `DELETE /api/settings/providers/{id}` | 生效中（is_active）→ 409；否则 204 |
| `POST .../providers/{id}/test` | 网关 healthcheck → `{ok, latency_ms, models: [...]}`；失败也给 200 + ok=false（测试结果不是错误） |
| `POST .../providers/{id}/activate` | 写 `settings.active_provider_id`，原 active 置否 → `{ok: true}`；进行中任务不受影响（发起时快照，对《03》§2.4 的实现化） |

### 12.3 设置 API 与 embedding 锁

**GET `/api/settings`** → `{"active_provider_id", "generation_params", "embedding", "embedding_locked": bool}`。

**PUT `/api/settings`**：可改 `generation_params`；`active_provider_id` 请走 activate；`embedding` 仅在 `embedding_locked=false` 时可改（用于建库前纠错）。首条向量写入后 `locked_at` 置位，此后任何 embedding 变更 → `409 EMBEDDING_LOCKED`，message 提示「向量库已建立，更换模型需清空全部文档后重建」（V1 不提供自动全库重算，列为 P2）。

### 12.4 数据导出（对《03》§4 的补充）

`GET /api/data/export` → `application/zip` 流式输出 `zone-kb-backup-{YYYYMMDD}.zip`：SQLite 在线备份（`sqlite3.Connection.backup` 到临时文件）+ `chroma/` + `storage/` 目录。仅此一个只读备份接口；导入恢复为手动替换数据目录（文档化，不做 API）。

**验收（M9 整体）**：providers 增删改测换全链；embedding 锁生效；export zip 可在空环境恢复启动。测试要点：activate 并发幂等；导出文件完整性（zip 条目清单断言）。

### 13.4 API/SSE 客户端约定

- axios 实例 `baseURL='/api'`；请求拦截注入 Bearer；响应拦截：401 → 清 auth 跳登录；其余按 §2.4 code 映射 ElMessage 文案。
- SSE 用 `@microsoft/fetch-event-source`（POST + headers 需要）；`onmessage` 按 event 分发（meta/token/citations/done/error）；AbortController 存 chat store，切会话/卸载即 abort。
- dev 代理：`vite.config.js` `server.proxy['/api'] → http://localhost:8000`。

**验收（F 整体）**：全页面按 §15 用例手工走通；轮询在无进行中任务时停止（Network 面板验证）；SSE 断流有用户可见错误态。

## 14. 安全与非功能实现

| 项 | 实现约定 |
|----|---------|
| api_key 保护 | Fernet 加密落库；仅网关内存解密；任何 API/日志不得出现明文（响应只给 has_api_key） |
| 上传安全 | 扩展白名单 + magic bytes 二次校验（pdf %PDF、docx/xlsx zip 头 PK、md 文本）；大小/数量上限见 §2.3 |
| 路径安全 | 所有落盘文件名系统生成（§6.4）；报告静态服务仅放行 `.html` 后缀且走安全静态接口（等价 send_from_directory） |
| XSS | Jinja2 autoescape 强制开启；笔记/聊天 markdown 渲染走 md-editor-v3 默认消毒；报告 iframe `sandbox="allow-scripts"`（不含 allow-same-origin） |
| SSE 资源 | 心跳 15s、总时长 300s、客户端断开即取消上游 LLM 流 |
| 性能预算 | 100 页 PDF 解析 ≤30s；检索 ≤1s；导入→笔记 ≤3min（云端主力预期值）；上传/生成接口入队响应 <1s；前端 dev 首屏 <2s |
