## 1. 开发环境准备

| 组件 | 操作 | 验证方式 |
|------|------|---------|
| 云端 API（**生成主力，必配**） | 任一 OpenAI 兼容服务（GLM / DeepSeek），申请 key | 网关连接测试通过 |
| Ollama（默认本地兜底） | 官网安装 → `ollama pull qwen3:4b` → `ollama pull bge-m3` | `curl http://localhost:11434/v1/models` 返回模型列表 |
| Ollama 上下文窗口 | 设置 `OLLAMA_CONTEXT_LENGTH=16384`（或 Modelfile 中 `num_ctx 16384`） | 长文档摘要不被截断（Spike 清单 #6） |
| LM Studio（可选本地兜底） | 安装 App → 下载 qwen3:4b（优先 MLX 版）→ 开发者页启动本地服务（:1234）→ context length 调至 16k | `curl http://localhost:1234/v1/models` |
| Python | 3.11+，用 uv 管理依赖 | `uv --version` |
| Node | 20 LTS（前端 Vite 要求） | `node -v` |

> **本地模型选型原则（2026-10-19 修订）**：生成质量最终靠云端 API；本地模型仅用于离线兜底与低成本联调，下载时只求速度——默认 `qwen3:4b`（约 2.5GB），**不下载 8B 级大模型**；若 4b 仍嫌慢可降至 `qwen3:1.7b`。bge-m3 为向量模型（约 1.2GB），因「向量库一致性」固定本地，不属于生成大模型范畴。

> **embedding 约定**：向量模型一经建库不得更换端点（换模型 = 全库重算）。默认用 Ollama 的 bge-m3；若只用 LM Studio，则用其 `/v1/embeddings` 并在 settings 中固化记录。

## 2. LLM 网关规格（`backend/app/llm/`）

### 2.1 统一接口

```python
class LLMGateway:
    def chat(self, messages: list[dict], *, temperature: float = 0.2,
             stream: bool = False) -> str | Iterator[str]: ...
    def chat_json(self, messages: list[dict], schema: dict) -> dict:
        """结构化输出：本地用 JSON Schema 约束；失败重试 2 次后抛 GatewayError"""
    def embed(self, texts: list[str]) -> list[list[float]]:
        """固定走 embedding 专用配置（见 §1 embedding 约定），不受供应商切换影响"""
```

### 2.2 Provider 抽象：三类端点一套实现

全部走 OpenAI 兼容协议，仅配置不同：

| provider_type | 默认 base_url | api_key | 用途 |
|---------------|--------------|---------|------|
| `cloud` | 如 `https://open.bigmodel.cn/api/paas/v4` | 必填，加密存储 | **生成主力（默认生效）** + 对比实验 |
| `local-ollama` | `http://localhost:11434/v1` | 占位符 | 向量（固定）+ 离线兜底生成（qwen3:4b 小模型） |
| `local-lmstudio` | `http://localhost:1234/v1` | 占位符 | 兜底生成备选（MLX 提速） |

### 2.3 调用记账（论文数据源）

每次调用写入 `llm_call_log(provider_id, model, task_type, prompt_tokens, completion_tokens, latency_ms, ok, error)`。性能对比图表直接从这张表出。

### 2.4 切换与降级语义

- `settings.active_provider_id` 唯一生效；任务发起时把供应商快照写入 `agent_task.provider_id`（结果可追溯）。
- 生成类调用失败重试 2 次 → 任务标记失败并提示「可切换另一供应商重试（云端 ↔ 本地小模型，切本地时质量可能降级）」；**不自动静默切换**，保证实验数据纯净。
- 任务发起前做健康检查（`GET /v1/models`）；LM Studio 服务随 App 关闭而停止，是常见故障源。

### 2.5 qwen3 特殊处理

qwen3 系列默认带思考模式，输出可能含 `<think>...</think>` 段。网关统一在响应层剥离；亦可在请求参数中关闭思考以降低延迟（整理类任务不需要深度思考时）。

## 6. Prompt 与结构化输出策略

**全局约束（拼入所有生成类 system prompt）**：
> 仅基于提供的资料片段作答；每条结论必须标注引用 `[doc_id:block_id]`；资料不足以支撑的问题，明确回答"知识库中未找到依据"，禁止编造。

**核心 JSON Schema**：
- 笔记：`{title, summary, key_points:[{point, citations:[{doc_id, block_id}]}], tags[], open_questions[]}`
- 报告大纲：`{title, sections:[{heading, key_points[], source_doc_ids[]}]}`
- 图表规格：`{type(bar/line/pie), title, x_field, y_field, data_source_block_id}`

**结构化输出实测策略（云端 + 本地 qwen3:4b）**：Ollama 用 structured outputs（json_schema format），LM Studio 用 `response_format: json_schema`，云端按各家 JSON mode 支持情况适配；解析失败 → 附错误信息重试 1 次 → 降级为正则提取 → 仍失败则任务失败（不静默产出脏数据）。

**温度约定**：抽取/整理 0.1–0.3；问答 0.3；报告写作 0.4。

## 9. 工程细节风险速查

| 坑 | 对策 |
|----|------|
| Ollama 默认上下文仅 2k/4k | 环境变量 / num_ctx 显式设 16k，Spike #6 专门验证 |
| LM Studio 服务随 App 退出而停止 | 任务发起前健康检查；设置页显示运行时在线状态 |
| qwen3 输出带 `<think>` 段 | 网关统一剥离（§2.5） |
| Playwright 首次需下载浏览器内核 | 安装脚本固化；网页解析失败降级为纯文本抓取并明确提示 |
| Chroma 与 SQLite 路径混乱 | 统一 `data/` 目录约定，写入 settings |
| 换 embedding 模型导致全库失效 | settings 固化 embedding 配置 + 更换前二次确认弹窗 |
